# Контекст для ИИ-агентов

Краткая инструкция для работы с кодом AllTell. Используйте её как указатель,
а не как замену проверке реализации.

## Перед изменением

1. Начните с [`docs/agent-context/README.md`](docs/agent-context/README.md):
   это индекс контекста и инструкция, какие страницы загружать для конкретной
   задачи.
2. Найдите домен в [`docs/agent-context/DOMAINS.md`](docs/agent-context/DOMAINS.md),
   затем откройте только нужные справочники API, данных и frontend.
3. Прочитайте соответствующие route, service/store и клиентский код; выясните,
   где хранится затрагиваемое состояние.
3. Проверьте текущие `git status` и локальные изменения. Не перезаписывайте
   пользовательские правки и данные.
4. Перед изменением формата данных, API, прав доступа или бэкапов найдите все
   связанные стороны (клиент, сервер, хранилище, миграции/восстановление).

## Устройство проекта

- Backend: CommonJS на Node.js + Express; вход `src/server.js`.
- Frontend: файлы без сборки из `public/`; основные страницы — SPA, HTML экранов
  лежит в `public/views/`.
- Маршруты — `src/routes/`; бизнес-логика и stores — `src/services/`; SQLite —
  `src/db/`.
- Статьи — JSON с деревом блоков, не Markdown-файлы. Данные карты тоже в JSON;
  большие исходные подложки и базы — пользовательские данные вне Git.
- Структура и быстрый поиск: [`docs/PROJECT_MAP.md`](docs/PROJECT_MAP.md).
- Подробные домены, API, данные, потоки и клиентские модули:
  [`docs/agent-context/`](docs/agent-context/README.md).
- План публичной основы и гостевого чтения Antropedia:
  [`CLIENT_SITE_PLAN.md`](docs/agent-context/CLIENT_SITE_PLAN.md).

## Правила работы

- Следуйте существующим соглашениям и делайте минимальные связанные изменения.
- Не добавляйте зависимости, сборщик или абстрактный слой без необходимости.
- Не коммитьте секреты, `.env`, базы данных, содержимое `content/` и загрузки.
- При изменении поведения обновляйте соответствующую agent-context страницу,
  только если она стала неверной; не дублируйте одну и ту же справку.
- Обновляйте `DEVLOG.md` для заметной завершённой функциональности, а не для
  каждой мелкой правки.
- В `package.json` нет тестовых, линтерных и сборочных скриптов. Выберите
  проверку по изменённому поведению и сообщите, если автоматической проверки
  нет.

## Команды

- `npm start` — сервер.
- `npm run dev` — сервер с nodemon.
- `npm run make-owner` и `npm run migrate-articles` — служебные операции;
  предварительно изучите скрипт и условия запуска.
- `npm run docs:api-index` — обновить полный индекс маршрутов из `src/routes/`.

## Обновление карты проекта

Если меняется ответственность модуля, место хранения данных, основной маршрут
вызова или команда разработки, синхронно поправьте `docs/PROJECT_MAP.md` либо
README. Не дублируйте в документации длинные описания реализации, которые
быстро устаревают.
