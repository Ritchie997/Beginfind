# AllTell

AllTell — веб-приложение на Node.js и Express. Оно объединяет мессенджер,
серверы и роли, Antropedia (статьи), интерактивные карты, галерею, стикеры,
уведомления и инструменты администрирования. Интерфейс — статическое
одностраничное приложение в `public/`; серверные API и бизнес-логика — в `src/`.

## Быстрый старт

Требуются Node.js и npm.

```bash
npm install
cp .env.example .env
# Укажите непустой случайный JWT_SECRET в .env
npm run dev
```

Сервер по умолчанию слушает `0.0.0.0:3002`. Для обычного запуска используйте
`npm start`. Не публикуйте `.env`, секреты, пользовательские базы, контент или
загруженные файлы.

Если после установки зависимостей сервер падает с `Could not locate the
bindings file` для `sqlite3`, разрешите выполнение install script пакета
`sqlite3` средствами своего package manager и выполните `npm rebuild sqlite3`.
После этого проверьте модуль командой
`node -e "require('sqlite3'); console.log('sqlite3 OK')"` и перезапустите сервер.

Основные npm-команды:

| Команда | Назначение |
| --- | --- |
| `npm start` | Запустить сервер |
| `npm run dev` | Запустить сервер с nodemon |
| `npm run make-owner` | Запустить служебный скрипт назначения владельца |
| `npm run migrate-articles` | Запустить миграцию статей |
| `npm run docs:api-index` | Пересобрать индекс API из router-объявлений |

Перед запуском служебных скриптов проверьте их исходный код и актуальные
требования к аргументам/окружению.

## Публичная основа и Antropedia

У приложения две поверхности:

| Поверхность | URL | Доступ |
| --- | --- | --- |
| Публичная основа | `/` | Без входа |
| Каталог Antropedia | `/antropedia` | Без входа |
| Открытая статья | `/antropedia/:slug` | Без входа; доступность проверяется сервером |
| Админ-панель | `/admin-panel` | Требуется вход |
| Админская Antropedia | `/admin-panel/antropedia` | Требуется вход |
| Просмотр статьи в админке | `/admin-panel/antropedia/:slug` | Требуется вход и существующие права |

Входы `/index.html`, старые HTML-адреса и `/site/*.html` сохранены для
совместимости. Публичная Antropedia читает статьи через `GET /api/public/articles`
и `GET /api/public/articles/:slug`. Список принимает `q`, `tag`, `limit` и
`offset`; скрытые статьи и слои не должны попадать в каталог, поиск или
публичный ответ. Изменяющие и социальные API остаются за авторизацией.

Ссылки для пересылки используют публичный `/antropedia/:slug`. Для открытых
статей сервер добавляет canonical, Open Graph и Twitter metadata в HTML до
загрузки JavaScript, чтобы preview-боты могли их прочитать. Для проверки
реальной карточки в мессенджере нужен доступный внешний HTTPS адрес; localhost
для этого не подходит.

### Локальная проверка публичной стороны

Запустите сервер (`npm run dev`) и проверьте:

1. `http://localhost:3002/antropedia` — каталог открывается без входа.
2. `http://localhost:3002/api/public/articles` — возвращается JSON-каталог.
   Выберите slug из `data` и откройте `/antropedia/<slug>` напрямую, затем
   обновите страницу.
3. В `Ctrl+U` на открытой статье проверьте `<title>`, `canonical`,
   `og:title`, `og:description` и `og:url`; заголовок должен соответствовать
   статье. Для закрытой или отсутствующей статьи ожидается одинаковая
   нейтральная страница 404 без её приватных метаданных.
4. Перейдите с публичной статьи в админ-панель. После входа должен сохраниться
   slug для перехода к редактору; редактирование всё равно ограничивается
   серверной проверкой прав. Из просмотра статьи в админке кнопка «Основа»
   возвращает на её публичный адрес.
5. Проверьте перезагрузку, браузерные «Назад/Вперёд» и мобильную ширину.

Автоматизированные проверки: `npm test`, `node --check src/routes/pages.routes.js`,
`node --check public/site/site.js` и `git diff --check`. Отдельных браузерных
тестов, линтера и frontend build-команды пока нет.

## Структура

```text
src/
  server.js          запуск Express, middleware, подключение маршрутов и фоновых задач
  config/            окружение и пути
  db/                общие SQLite-подключения и миграции
  middleware/        аутентификация, техобслуживание, дедупликация запросов
  routes/            HTTP/API-слой по функциям
  services/          бизнес-логика и файловые хранилища
  uploads/           конфигурация приёма файлов
public/
  index.html         оболочка приложения и подключение ресурсов
  *.js, *.css        клиентский код и стили
  views/             HTML-фрагменты экранов SPA
  maps/              клиент интерактивных карт
scripts/             служебные и миграционные скрипты
```

## Архитектурные ориентиры

- Серверный вход — `src/server.js`. Порядок важен: публичная статика и явные
  page routes регистрируются до API; общий SPA fallback — после API-маршрутов.
- Маршруты лежат в `src/routes/`, а бизнес-логика обычно вынесена в
  `src/services/`. При изменении функции ищите обе стороны, соответствующий
  клиентский модуль и связанные данные.
- Клиент не собирается отдельным frontend-сборщиком: скрипты и стили загружаются
  напрямую из `public/`; часть библиотек подключается из CDN.
- Данные приложения разделены между SQLite и файлами. Статьи — JSON-документы
  с блоками в `content/`, интерактивные карты и настройки миров — JSON в
  `content/maps/` и `content/worlds/`. Точные границы описаны в
  [`docs/PROJECT_MAP.md`](docs/PROJECT_MAP.md).
- Пользовательские данные и крупные исходники не входят в Git; для их сохранения
  предусмотрены серверные бэкапы.

## Настройка

Скопируйте `.env.example` в `.env`. Обязателен `JWT_SECRET`; без него приложение
не должно запускаться. `PORT` по умолчанию `3002`, `HOST` — `0.0.0.0`.
Укажите собственный криптографически случайный секрет и не коммитьте `.env`.

## Проверки

`npm test` запускает автоматические интеграционные проверки публичных/
административных маршрутов и безопасного гостевого чтения статей. Отдельных
lint- и build-команд пока нет; перед запуском изменений проверяйте затронутые
участки этим тестом и обычными проверками синтаксиса Node.js.

## Хранение данных и резервное копирование

Серверные базы SQLite, `content/`, `public/uploads/` и исходники карт являются
данными среды, а не исходным кодом. Часть путей исключена из Git через
`.gitignore`. Создание и восстановление ZIP-бэкапов реализованы в
`src/services/backup.js` и соответствующих маршрутах. Перед изменением состава
бэкапа проверьте и добавление, и восстановление файлов.
