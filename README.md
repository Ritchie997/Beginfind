# BeginFind Server

Серверная часть приложения BeginFind: мессенджер, система "серверов" (каналы/роли/участники, по образцу Discord) и Ibripedia — вики-модуль со статьями.

## Установка зависимостей

```bash
npm install
```

## Переменные окружения

Перед запуском сервера создайте файл `.env` в корне проекта на основе `.env.example`:

```bash
cp .env.example .env
```

Доступные переменные:
- `PORT` — порт для сервера (по умолчанию: 3002)
- `HOST` — хост для сервера (по умолчанию: 0.0.0.0)
  - Для локальной разработки: `localhost`
  - Для доступа из локальной сети или деплоя (Render.com и т.п.): `0.0.0.0`
- `JWT_SECRET` — **обязателен**. Сервер не запустится без него (раньше был небезопасный дефолт).
  Сгенерировать: `node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"`
- `JWT_EXPIRES_IN`, `JWT_REFRESH_EXPIRES_IN` — время жизни токенов
- `ROOT_USERNAME`, `ROOT_PASSWORD` — использовались для создания root-аккаунта одноразовым
  скриптом (уже выполнен и удалён из репозитория); можно убрать из `.env` после создания root-аккаунта

## Запуск сервера

### В режиме разработки
```bash
npm run dev
```

### В продакшен режиме
```bash
npm start
```

Оба скрипта запускают `src/server.js`. Сервер будет доступен по адресу: http://localhost:3002

`npm run dev` использует `nodemon` с конфигом `nodemon.json`: он следит только за
`src/` и `public/` и явно игнорирует `content/**`, `backups/**`,
`public/uploads/**`, `*.db` и `backup-settings.json` — каталоги/файлы, куда
сам сервер пишет во время работы. Без этого runtime-запись (например,
создание `backup-settings.json` при первом старте) вызывала перезапуск
nodemon, а тот — новую запись, что приводило к бесконечному циклу рестартов.

## API Endpoints

### Аутентификация
- `POST /api/register` — регистрация (статус `pending` до подтверждения)
- `POST /api/login` — вход
- `GET /api/profile` — профиль текущего пользователя
- `GET /api/pending-users`, `PUT /api/pending-users/:id/approve|reject`, `GET /api/all-users` — управление заявками (root only)

### Мессенджер
- `GET /api/messages` — получить все сообщения
- `POST /api/messages` — отправить сообщение (имя отправителя берётся из токена)

### Дашборд (аналитика)
- `GET /api/dashboard-summary` — сводка для страницы "Аналитика" (`src/services/dashboard-stats.js`):
  `users` (подтверждённые пользователи: всего и за 7 дней), `messages` (только сообщения мессенджера:
  всего, за 7 дней и `daily` — счётчики по дням для спарклайна), `comments` (комментарии статей
  Ibripedia: всего, за 7 дней и `articles` — в скольких статьях есть обсуждение; комментарии
  удалённых статей не считаются) и
  `recent` — свежие регистрации, комментарии и сообщения для ленты "Последняя активность"
  (комментарии к недоступным пользователю закрытым статьям отсеиваются). Статьи и серверы дашборд
  берёт из `/api/articles` и `/api/servers`.

Записи ленты "Последняя активность" кликабельны: статья и комментарий — открывают статью в
Ibripedia (комментарий — сразу на блоке комментариев), сервер — вкладку "Сервера" с его именем в
строке поиска, регистрация — профиль пользователя (`/profile/:id`). Сообщения мессенджера — просто
строка, открывать нечего.

### Ibripedia (вики)
- `GET /api/articles` — список статей (закрытые по ролям статьи видны только тем, у кого есть доступ);
  фильтры `?since=`, `?server=`, `?tag=`
- `GET /api/articles/:slug` — статья по slug (раньше был числовой id, см. "Хранение статей")
- `POST /api/articles` — создать статью
- `PUT /api/articles/:slug` — обновить статью (если сменился заголовок, упоминания
  статьи `[[wiki-ссылками]]` в остальных статьях тоже обновляются; slug не меняется)
- `PUT /api/articles/:slug/rename` — переименовать (меняет title и slug, обновляет
  `[[wiki-ссылки]]` на неё во всех остальных статьях)
- `DELETE /api/articles/:slug` — удалить статью (перемещается в content/.trash/, не стирается);
  её упоминания `[[wiki-ссылками]]` в остальных статьях заменяются на текст «Удалено»
- `GET /api/articles/:slug/backlinks` — статьи, ссылающиеся на данную через `[[wiki-ссылку]]`
- `GET /api/articles-index` — облегчённый список {slug, title, tags} для автодополнения `[[` в редакторе
- `GET /api/articles-graph` — узлы+рёбра для графа связей
- `GET /api/search-articles?q=...` — поиск по заголовку/содержимому
- `GET /api/tags` — глобальный список всех тегов без дублей: `[{tag, count}]` (теги из поля «Теги» и #хэштеги
  из текста; регистр и ведущий `#` не различаются; только статьи, доступные пользователю) — вкладка «Теги»
- `GET/POST/DELETE /api/roles` — глобальный справочник ролей (изменение — root only)

### Серверы (каналы/роли/участники)
- `GET/POST/PUT/DELETE /api/servers[/:id]` — CRUD серверов (обновление/удаление — владелец или root)
- `GET /api/servers/:id/users`, `GET/POST /api/servers/:id/roles`
- `POST /api/servers/:serverId/users/:userId` — вступление (себя) или добавление участника (админ сервера)
- `POST/DELETE /api/servers/:serverId/users/:userId/roles/:roleId` — назначение/снятие роли
- `PUT/DELETE /api/servers/:serverId/roles/:roleId` — изменение/удаление кастомной роли
- `PUT /api/servers/:serverId/owner` — смена владельца сервера (root only)
- `GET /api/users` — список пользователей для выбора нового владельца (root only)

### Загрузка файлов
- `POST /api/upload-image` — загрузка изображения (jpg/jpeg/png/gif/webp, до 5MB)

### Бэкапы (root only)
- `GET /api/backups`, `POST /api/backups/create`, `POST /api/backups/upload`,
  `POST /api/backups/restore/:fileName`, `GET /api/backups/download/:fileName`,
  `DELETE /api/backups/:fileName`, `GET/PUT /api/backups/auto/settings`, `POST /api/backups/auto/run`

## Хранение статей (content/)

С Этапа 3 статьи Ibripedia хранятся не в БД, а как Markdown-файлы:
`content/<slug>.md`, где `slug` — транслитерированный заголовок
(`src/services/slugify.js`), он же id статьи в URL и цель wiki-ссылок
`[[slug]]`. Каждый файл — YAML-frontmatter + тело в Markdown:

```markdown
---
title: Заголовок статьи
date: '2026-04-09T15:19:39.000Z'
updated: '2026-04-09T15:19:51.000Z'
author: ''
tags: []
category: ''
excerpt: ''
server: null       # id или имя "сервера", к которому привязана статья
locked: false       # если true — видна только по ролям ниже
roles: []           # id ролей сервера, у кого есть доступ при locked=true
image: null         # обложка
attachments: []
views: 0
---
Текст статьи в Markdown.
```

- Удаление перемещает файл в `content/.trash/` (не безвозвратно).
- Список статей кэшируется в памяти (`src/services/articles-store.js`) и
  инвалидируется при любой записи через API или восстановлении бэкапа.
- Резервные копии (`/api/backups/*`) включают все базы данных (в том числе `stickers.db`), `content/` целиком, `public/uploads/` (картинки статей и файлы стикеров) и `system-settings.json`/`cleanup-settings.json`. Восстановление заменяет базы и настройки целиком, а статьи и файлы записывает поверх текущих (лишнее не удаляет); после него нужен перезапуск сервера.

## Редактор статей (в стиле Obsidian)

С Этапа 4 форма статьи (`public/views/articles.html`, логика — `public/editor-manager.js`)
использует CodeMirror 6 вместо старого contenteditable-редактора:

- **Markdown**: заголовки, списки (в т.ч. чек-листы `- [ ]`), цитаты, код
  (строчный и блоки), таблицы, горизонтальные линии — через тулбар или
  напрямую руками.
- **Режимы**: "Редактирование" / "Просмотр" / "Разделить" (слева редактор,
  справа live-превью) — переключаются кнопками над редактором.
- **Wiki-ссылки** `[[Название статьи]]`, `[[slug|текст]]` или со своим именем
  в круглых скобках сразу после `]]` — `[[статья]](Анатолий)` (ссылка ведёт на
  «статью», а подписана «Анатолий»; если заданы и `|текст`, и `(имя)`, побеждает
  `(имя)`; классические markdown-ссылки `[текст](url)` не затрагиваются):
  подсвечиваются
  синим (статья существует) или красным (не существует, при клике в превью —
  предложение создать); автодополнение по вводу `[[` в редакторе.
  В самом CodeMirror переход по ссылке — Ctrl/Cmd+клик (чтобы не мешать
  редактированию текста), в панели "Просмотр" — обычный клик.
  Ссылка без своего текста (`[[цель]]`, не `[[цель|текст]]`) показывает
  актуальное название статьи, а не набранное в тексте. Упоминания защищены от
  переименования и удаления: при смене заголовка/slug цель ссылки (алиас
  `|текст` и `(имя)` сохраняются) переписывается во всех статьях, при удалении
  статьи ссылка на неё (вместе с `(именем)`) заменяется на «Удалено» (см. `refreshMentions`/`deleteArticle`
  в `src/services/articles-store.js`). Правка идёт по тексту статей на диске —
  возврат статьи из корзины ссылки обратно не восстанавливает.
- **Теги** `#тег` прямо в тексте (плюс теги из формы/frontmatter) —
  подсвечиваются, клик открывает список статей с этим тегом.
- **Backlinks**: под формой статьи, при редактировании существующей —
  список статей, ссылающихся на неё.
- **Горячие клавиши**: Ctrl+B (жирный), Ctrl+I (курсив), Ctrl+K (ссылка),
  Ctrl+S (сохранить), Ctrl+Shift+F (перейти к поиску по статьям).
- Переименование статьи со сменой slug и автоматическим обновлением ссылок —
  через `PUT /api/articles/:slug/rename` (см. выше; UI-кнопка переименования
  использует этот эндпоинт).

CodeMirror 6, `marked` (рендер Markdown в превью) и `DOMPurify` (санитайзинг
HTML превью) подключаются во время выполнения из CDN (esm.sh/jsDelivr) через
динамический `import()` — в проекте нет сборщика фронтенда, поэтому пакеты
не лежат в `node_modules` браузерной части и не требуют build-шага. Версии
`@codemirror/*` пакетов зафиксированы точно и явно согласованы через параметр
`?deps=` у esm.sh, чтобы все части CodeMirror ссылались на один и тот же
экземпляр `@codemirror/state`/`@codemirror/view` (иначе бросает ошибки
несовместимых расширений).

Тулбар сгруппирован по смыслу (текст / заголовки / списки / код-цитаты /
вставки), под ним — переключатель режимов. Стили — `public/editor-obsidian.css`
и встроенный `<style>` в `public/views/articles.html`; палитра сайта не
менялась, обновлены только компоновка, отступы и типографика (шрифт текста —
как на остальном сайте, моноширинный остаётся только для `код`/```блоков```).
Кнопки формы разведены по значимости: черновик (второстепенное) — слева,
сброс (приглушённая "ghost"-кнопка, чтобы не спутать с публикацией по
соседству) и публикация (основная кнопка) — справа.

В превью `marked` подключён с `breaks: true` — одиночный Enter даёт перенос
строки, как в Obsidian по умолчанию, а не игнорируется до пустой строки, как
того требует строгий CommonMark.

Поле заголовка — одно на редактирование и на переименование: обычное
сохранение меняет только текст заголовка в статье и не трогает slug/адрес
(см. `updateArticle` в "Хранение статей" выше), а если текущее значение поля
отличается от заголовка, с которым статья была загружена, под полем
появляется подсказка "Переименовать и обновить ссылки" — она вызывает
`PUT /api/articles/:slug/rename` прямо со значением поля, без повторного
запроса текста.

## Граф связей

По аналогии с графом связей Obsidian: точки — статьи, линии — `[[wiki-ссылки]]`
между ними. Реализован в `public/graph-view.js` (SVG + `d3-force`, тоже
загружается динамически с CDN через esm.sh с `?deps=` для согласования версий
d3-пакетов, как и CodeMirror выше) и используется в двух местах:

- **Карточка на дашборде** (`/dashboard`, "Граф связей статей", под графиком
  активности) — граф по всем статьям. `GraphView.initGraphPage()` универсален:
  ему достаточно `#graphContainer`/`#graphNodeCount` в разметке, поэтому
  отдельная страница/маршрут `/graph` не нужны — раньше граф был там.
- **Локальная панель** в редакторе статьи (под backlinks) — граф только из
  текущей статьи и её прямых соседей.

Поведение: наведение на точку увеличивает подпись ("как через лупу", за счёт
CSS `transform: scale()`) и подсвечивает связанные рёбра, приглушая остальные;
клик по точке переходит в редактор соответствующей статьи; колесо мыши/драг —
зум и панорамирование холста (`d3-zoom`/`d3-drag`). Данные берутся из
`GET /api/articles-graph` (узлы несут `server`/`category` — нужны фильтрам ниже).

Карточка на дашборде дополнительно даёт:

- **Фильтр по серверу** — реально убирает узлы/рёбра чужих серверов из графа
  (пересчитывает и перерисовывает граф), а не просто приглушает.
- **Поиск по названию** — не убирает узлы, а подсвечивает совпадения и их
  прямые связи, приглушая остальное (`instance.setSearchHighlight(query)`);
  сочетается с наведением мышью — оно временно перекрывает подсветку поиска,
  а после ухода курсора подсветка возвращается к текущему запросу поиска.
- **"Скрыть изолированные"** — чекбокс, убирает из графа статьи без единой
  `[[ссылки]]` на других или с других.
- **Экспорт в PNG** — текущий вид графа (с учётом применённого зума) как
  картинка; переносит реальные вычисленные CSS-цвета на клон SVG перед
  сериализацией, иначе PNG вышел бы бесцветным (внешний `editor-obsidian.css`
  в сериализованный SVG не попадает).

## Базы данных

Сервер использует SQLite для остальных данных:

1. **messenger.db** — сообщения мессенджера
2. **users.db** — пользователи и роли
3. **articles.db** — устаревшая (сами статьи — в `content/`, см. выше); справочник категорий из неё удалён
4. **servers.db** — серверы, роли на серверах и участники

## Веб-интерфейс

Сервер обслуживает статические файлы из папки `public/` (одностраничное приложение).

## Разработка

- Node.js + Express.js
- SQLite3 (мессенджер, серверы, пользователи)
- gray-matter для чтения/записи Markdown-frontmatter статей, turndown — для миграции HTML в Markdown
- JWT (jsonwebtoken) + bcryptjs для аутентификации
- Multer для загрузки файлов, adm-zip для бэкапов
- Nodemon для автоматической перезагрузки при изменениях
