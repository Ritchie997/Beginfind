# План: публичная клиентская версия AllTell

Этот документ фиксирует целевое направление, текущий статус реализации и
дальнейшие этапы. Перед началом каждого этапа сверяйте его с актуальным кодом
и уточняйте детали интерфейса, которых нет в исходном запросе.

## Цель и границы

У AllTell будет две переключаемые поверхности:

1. **Основа / клиентская версия** — публичный сайт для читателей. Открытые
   статьи Antropedia можно читать без регистрации.
2. **Админ-панель** — существующее авторизованное рабочее приложение: создание
   и редактирование статей, настройки, управление серверами и другие имеющиеся
   инструменты.

Админ-панель рассматривается как отдельный рабочий режим поверх общей основы,
а не как целевая страница для читателя. Между режимами есть явный переключатель
в шапке/навигации. Ссылка, которой делятся статьёй, всегда открывает публичную
сторону; она не должна приводить в админ-панель и требовать вход для открытой
статьи.

**Базовая функциональность:**

- публиковать открытую основу с данными из серверных источников;
- подключить Antropedia как доступную для чтения витрину;
- разрешить анонимное чтение открытых статей, сохранив ограничения закрытых
  статей/слоёв;
- направлять share-ссылки статей в публичный просмотр;
- оставить все операции редактирования и администрирования за текущей
  авторизацией.

Главная показывает актуальные открытые статьи и галерейные работы, счётчики
из серверной аналитики и граф связей публичных статей. Техобслуживание
настраивается независимо для главной, AllTell, Antropedia и галереи; доступ к
админ-панели при этом сохраняется. Экран обслуживания сохраняет общую
навигацию основы, поэтому посетитель может перейти в другой открытый раздел
без перезагрузки сайта. Профиль доступен в публичной оболочке и использует
существующие API и проверки доступа.

## Что есть сейчас

- `public/site/*.html` и `public/site/site.css` содержат публичную оболочку;
  `public/site/router.js` выполняет внутренние переходы через History API и
  подмену контента без полной перезагрузки, сохраняя прямые URL и back/forward.
  Antropedia (`public/site/antropedia.html`, `site.js`) использует публичный
  API для гостей и авторизованный API для вошедших пользователей; главная
  получает статьи, статистику и галерейные работы из API. В шапке
  есть авторизованное меню профиля и кнопка входа для гостя;
  форма входа предлагает перейти к регистрации. Страница профиля —
  `public/site/profile.html` и `profile.js` — использует общий стиль витрины.
- AllTell (`/alltell`) загружает каталог только опубликованных франшиз из
  `/api/public/franchises`. Страница франшизы показывает все хабы и их статусы,
  публикации, а вошедший пользователь может вступить через существующее
  членство. Создатель/администратор управляет публикациями в публичной карточке;
  новости, объявления и события могут относиться к франшизе или конкретному
  хабу. Для участника открытие ленты отмечает её публикации прочитанными;
  счётчик новых публикаций отображается в «Моём AllTell». Черновик франшизы
  видит только её создатель/администратор; в общем каталоге он появляется лишь
  после публикации.
- Профиль использует авторизованные API; редактирование имени, аватара и bio
  доступно владельцу профиля. Приватная заметка отображается только при
  серверном `can_edit_note` (`view_users_tab` или root); запись повторно
  проверяется сервером на `PUT /api/users/:id/note`.
- `public/index.html` — приложение админ-панели. `/admin-panel` отдаёт его,
  `/index.html` сохранён как прямой legacy-вход, а SPA fallback поддерживает
  прежние административные URL.
- Админское чтение статей реализовано в `public/antropedia.js`; внутренний URL
  статьи использует `/admin-panel/antropedia/:slug`, а share — публичный
  `/antropedia/:slug`.
- `GET /api/articles`, `/api/articles/browse` и `GET /api/articles/:id`
  защищены `authenticateToken` и `checkApproved`; гостевое чтение реализовано
  отдельными endpoints `/api/public/articles*`.
- Доступ к статье/слою централизован в
  `src/services/article-layers.js`: админские запросы используют резолвер
  пользователя, а гостевые — отдельный `resolvePublicArticleLayers` без
  фиктивного пользователя. Статьи и их слои могут быть закрыты по ролям.
- Лайки, комментарии, реакции, закладки, граф, расширенные метаданные и
  редакторские данные используют авторизованные API. Публичное чтение не
  должно случайно открыть запись или приватные поля.

Проверяемые исходники: `src/server.js`, `src/routes/pages.routes.js`,
`src/routes/articles.routes.js`, `src/services/article-layers.js`,
`src/services/articles-store.js`, `public/antropedia.js`,
`src/routes/franchises.routes.js`, `src/routes/servers.routes.js`,
`public/spa-router.js`, `public/site/*.html`, `public/site/site.js`,
`public/site/alltell-client.js`,
`public/site/router.js`.

## Адресная модель

Канонические пути первой реализации:

| Назначение | Канонический путь |
| --- | --- |
| Публичная главная / основа | `/` |
| Публичная Antropedia | `/antropedia` |
| Публичная статья | `/antropedia/:slug` |
| Публичный AllTell | `/alltell` |
| Публичная галерея | `/gallery` |
| Админ-панель | `/admin-panel` |
| Админский просмотр статьи | `/admin-panel/antropedia/:slug` |
| Переход в редактор статьи | `/admin-panel?editArticle=:slug`, затем `/articles` после входа |

Существующие `/site/*.html` оставлены рабочими legacy-страницами. `/index.html`
остаётся прямым статическим entry point админ-панели, а старые `.html` страницы
админки и прежние SPA paths продолжают отдавать её оболочку. Старые
`/antropedia/:slug` ссылки теперь получают публичную оболочку, а не HTML админки.

Маршруты настроены явно и до SPA catch-all. Статический ресурс не должен
попадать в fallback. Внутренние переходы по wiki-ссылкам публичной статьи
должны сохранять публичный префикс; переход в редактор — только через кнопку
админ-режима и с существующей проверкой прав.

## План работ

### Этап 1. Контракты и маршруты — выполнен

Выполнено в первом routing change:

- `/` отдаёт публичную главную страницу `public/site/index.html`.
- `/antropedia` и `/antropedia/:slug` отдают публичную оболочку
  `public/site/antropedia.html`; открытая статья загружается из гостевого API,
  а metadata preview сервер формирует до загрузки JavaScript.
- `/admin-panel` открывает существующее приложение админ-панели; внутри него
  работают `/admin-panel` и `/admin-panel/antropedia`; админский просмотр
  статьи использует `/admin-panel/antropedia/:slug`.
- `/index.html`, `/admin-panel.html`, `/dashboard.html`, `/articles.html`,
  `/tags.html`, `/roles.html`, `/settings.html`, старые `/site/*.html` и прежние
  SPA paths (`/dashboard`, `/articles`, `/tags`, `/servers` и другие) сохранены
  как совместимые входы/адреса. `/index.html` по-прежнему является прямым
  статическим входом в админку.
- Текущие кнопки перехода с публичных страниц ведут на `/admin-panel`.

Технически статика настроена с `index: false`, чтобы `/` отдавал публичную
страницу, а `/index.html` продолжал получать админский HTML. Совместимые
`.html` маршруты обслуживает `src/routes/pages.routes.js`; прочие legacy SPA URL
принимает общий fallback.

Ограничение совместимости: `/antropedia` и `/antropedia/:slug` раньше
использовались админской SPA. Поскольку это канонический публичный адрес
Antropedia и адреса пересылок, они теперь отдают публичную оболочку. Переходы
из админской навигации перенесены на `/admin-panel/antropedia`; внутренние URL
просмотра статьи используют `/admin-panel/antropedia/:slug`, а share-кнопка
сохраняет публичный `/antropedia/:slug`. Уже открытая
или закэшированная админская SPA может продолжать работать по старому адресу,
но новая загрузка этих URL теперь публичная.

HTTP-маршруты покрыты интеграционным тестом. Проверка browser
reload/back-forward остаётся частью ручной проверки на развёрнутом экземпляре.

### Этап 2. Безопасное публичное чтение статей — первая реализация API

- Реализовано: отдельные `GET /api/public/articles` (список, поиск по `q`,
  фильтр `tag`, пагинация) и `GET /api/public/articles/:slug`; существующие
  авторизованные endpoints не менялись.
- Реализовано: используется общий нормализатор слоёв и отдельное правило
  гостевого доступа. Открытый legacy-слой виден; слой рядом с закрытыми
  ролями доступен гостю только с явным `public: true`. Если нет доступного
  публичного слоя, одиночный endpoint отвечает нейтральным 404, список,
  поиск, тег-фильтр и `total` не учитывают статью.
- Реализовано: ответ строится из allowlist полей выбранного публичного слоя,
  без сырых `layers`, ролей, вложений, серверных данных и прав; автор наружу
  передаётся только публичными полями для ссылки на профиль. Гостевой
  endpoint по-прежнему исключает карты и вставки работ галереи, чтобы не
  раскрывать ссылки на контент без публичной политики доступа.
- Реализовано: публичный интерфейс подключён к этим endpoints. Гостевые
  чтение wiki-графа, карт и галереи не реализованы и требуют отдельных правил
  доступа.
- Изменяющие и социальные endpoints остаются авторизованными; гостевые
  write endpoints не добавлялись.

**Важно для гостя:** не вызывать `resolveArticleLayer` с фиктивным `user.id`.
Для публичных API используйте `resolvePublicArticleLayers`, который не
обращается к пользовательским ролям; ошибки чтения не должны трактоваться как
публичный доступ.

### Этап 3. Публичная Antropedia

- Реализовано: каталог использует гостевой API для поиска, фильтров (теги,
  диапазон дат), сортировки (новые/старые/обновлённые/по просмотрам/по алфавиту)
  и подгрузки при прокрутке. Вошедший пользователь использует те же
  авторизованные `/api/articles/browse`, `/api/articles/:id` и `/api/articles-index`,
  что и админская Antropedia: каждый маршрут применяет общий резолвер слоёв,
  включая обход ограничений владельцем и доверенным администратором. Гостю
  остаются `/api/public/articles*` и только публичные слои. Теги для фильтра
  читаются через соответствующий публичный или авторизованный API. Карточка
  статьи построена как в админке (описание, автор с аватаром, теги, дата,
  счётчики и реакции). Лайк, реакции со стикерами и переход к комментариям
  доступны в карточке; статья показывает лайк, реакции и комментарии.
  Изменяющие действия требуют входа и используют авторизованные API. Пикер
  использует добавленные пользователем наборы стикеров; их добавление
  выполняется через авторизованный каталог.
- Реализовано: прямой `/antropedia/:slug` загружает открытую статью, а
  закрытая/несуществующая показывает одинаковое нейтральное сообщение.
  Есть состояния загрузки, пустой выдачи и ошибки. Вошедшим пользователям,
  которым сервер возвращает `can_edit`, показана кнопка перехода к этой
  статье в Antropedia админ-панели (`/admin-panel/antropedia/:slug`). На
  странице статьи скрыта hero-шапка с поиском, а обложка показывается над
  заголовком. Кнопка возврата в список сохраняет исходные фильтры и позицию
  прокрутки каталога; для восстановления при необходимости догружаются
  страницы списка.
- Реализовано: блоки отображаются существующим санитайзящим `blocks-renderer`;
  wiki-ссылки переходят на публичные `/antropedia/:slug`. Списки и счётчики
  берутся из API.
- Ограничение: гости не получают блоки карт и embeds галереи. Для
  аутентифицированного чтения публичной статьи блок карты отображается через
  существующий авторизованный API карты, который проверяет доступ читателя;
  отдельный публичный API карт не добавлялся. Вставки работ галереи пока не
  отображаются в публичном renderer.

### Этап 4. Переключение «Основа ↔ Админ-панель»

- Реализовано: заметный переключатель добавлен в публичную Antropedia и
  админскую шапку. Из админского просмотра статьи он сохраняет slug при
  переходе в публичную статью; из остальных разделов ведёт на публичную главную.
- Реализовано: публичная статья передаёт slug в
  `/admin-panel/antropedia/:slug`, открывая её просмотр в Antropedia
  админ-панели; доступ к статье проверяется авторизованным API.
- Реализовано: гостевой переход идёт на админскую страницу входа, публичный
  просмотр остаётся без авторизации; гостевой профиль и регистрацию не
  добавляли, фиктивные элементы профиля и уведомлений удалены из публичной
  оболочки.
- Проверка back/forward и мобильного отображения переключателей остаётся
  частью ручной проверки в браузере.

### Этапы 5–6. Share URL, совместимость и стабилизация

- Реализовано: share-кнопка админской Antropedia копирует/передаёт
  `/antropedia/:slug`; внутренний URL просмотра и кнопки редактирования в
  админке остаются на `/admin-panel/antropedia/:slug`.
- Реализовано: публичные wiki-ссылки получают прямые href на `/antropedia/:slug`;
  навигация основы использует канонические `/` и `/antropedia`. Старые
  `/site/*.html` и `/antropedia/:slug` адреса продолжают открывать публичную
  страницу.
- Реализовано: для доступной публичной статьи сервер отдаёт title, description,
  canonical, Open Graph и Twitter metadata до загрузки JavaScript; поля
  формируются из публичного DTO и HTML-экранируются. Закрытые статьи получают
  только общую оболочку без их метаданных. Клиент синхронизирует метаданные
  после загрузки статьи.
- Автоматизировано: тестируются прямой URL с кодированным slug, публичный
  canonical/preview, отсутствие метаданных закрытой статьи, разделение
  public/admin URL и гостевые правила видимости/поиска.
- Перед выкладкой остаётся ручной smoke-test в браузере: share/reload,
  мобильное меню, back/forward, реальный preview в мессенджере и вход с
  пользователем без права редактирования. Интеграционных браузерных тестов в
  проекте нет.

## Зависимости и порядок

```text
Согласовать URL/алиасы
      ↓
Явно разделить публичную и админскую оболочки
      ↓
Безопасный read-only API для гостя
      ↓
Публичный список и просмотр статьи
      ↓
Переключатель режимов и перевод share/wikilinks
      ↓
Совместимость, metadata и проверка прав
```

Публичная оболочка и API должны иметь ясные URL-контракты до переноса всех
ссылок. Этапы можно реализовывать небольшими PR; нельзя включать гостевой UI
раньше серверного фильтра по доступу.

## Не входит в первую очередь

- Переписывание админ-панели или перенос её функций на публичный сайт.
- Гостевая регистрация/создание аккаунта и социальная запись без авторизации.
- Публичные сообщения/чаты и новые роли членства на уровне хаба.
- Push- и email-уведомления для публикаций; первая версия использует ленту и индикатор непрочитанного.
- Новая ролевая модель, изменение существующих политик доступа.
- Полный SEO/SSR публичного сайта за пределами metadata страниц Antropedia.

## Принятые решения

1. Публичная основа использует `/`, админка — `/admin-panel`; `/index.html`
   сохранён как совместимый вход в админку.
2. Закрытая или отсутствующая публичная статья отображает одинаковую
   нейтральную страницу со статусом 404.
3. Сервер формирует Open Graph/Twitter metadata доступных статей для preview;
   проверка реальной карточки мессенджера требует публичного HTTPS deployment.
4. В публичный каталог попадают только франшизы, которые создатель явно
   опубликовал; новые/существующие франшизы по умолчанию скрыты.
5. Вступление действует на уровне франшизы. Участник видит все хабы,
   включая завершённые; отдельного членства в хабах нет.
6. Объявления, новости и события публикуются в общей ленте франшизы или
   конкретного хаба. Привязка к статье разрешена только для публично доступной
   статьи.
7. Индикатор непрочитанного относится к ленте франшизы; внешние push/email
   уведомления отложены.
